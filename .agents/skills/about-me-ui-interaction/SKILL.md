# About Me UI 交互

先看玩家在这个界面要完成什么，再看现有组件、输入方式和可用空间。选择一个主交互；只有在状态表达仍不足时才加辅助反馈。保持游戏已有的玩具贴纸风格、团结 UI 技术栈和数据流程，不为展示效果改写无关页面。

确定交互时回答：变化从哪个输入或元素开始；操作最终落在哪里；哪些邻近元素需要回应或让位；完成、取消、失败后分别显示什么。将“高级”“丝滑”“有质感”转为可实现的位移、尺寸、透明度、时序和状态规则。候选模式及适用边界见 [交互模式](references/patterns.md)。

实现时保持玩家操作与真实状态即时响应，动效只解释状态，不代替判定。快速重复输入从当前可见状态接续，最后一次有效选择获胜；取消应复位。按钮命中区域和文字保持稳定、可读。兼顾鼠标、键盘、横屏触控及安全区；触控动效不能挡住战斗或滚动。沿用现有“减少动态”设置，关闭大幅移动与持续视差后仍能识别当前状态。不要为了装饰默认读取手机姿态，也不要把碰撞反馈写成真实业务变化。

检查静止、连续点击、反向操作、取消、边界尺寸和恢复显示时的结果。记录代码检查、引擎运行、截图、真机与性能证据各自覆盖到哪里；没有实测的平台保持待验证。若用户只要选型或提示词，给出方案即可；要求落地时在指定界面实现。
