## 1. 对现有 UI 的实际观察

本轮读取了 `client/Assets/AboutMe/Runtime/UIArt.cs` 的 `UITheme` 和 `Surface()`，并查看 `artifacts/home-final.png`、`artifacts/ui-hud-v2.png`。截图用于观察风格，当前代码用于核对准确色值。

UI 的共同语言是奶油白/米白底、深蓝灰清楚轮廓、粉彩强调色、简单卡片分区、少量错位阴影与贴纸感。世界美术借用色彩、轮廓与分层关系。截图中旧 3D 角色的高光、地砖网格和旧障碍物不作为本次地图材质标准；也不把文字、按钮和面板直接搬到世界里。

颜色识别是“色块＋图标”，不只靠红绿或接近的粉紫色分辨。音乐音符、摄影相机、创客齿轮、动漫星形、篮球球形线纹、桌游骰子，各自只有一个大型主图标。图标从几何/矢量确定性制作后独立挂载，不依赖 Tripo 把六种符号同时猜对。

大面以中性色为主，建议画面大约 70% 中性色、25% 社团与引导色、5% 深色轮廓；这是构图指导，不是按三角面计算的硬比例。准确色值最终通过引擎共享材质落实，不能只凭生成图中的近似颜色验收。

## 2. 整体校园的完整美术描述

玩家站在校园正门，看到一处宽阔、有建筑围合感的大学社团中庭。左右楼翼和后方教学楼共同形成 U 形空间；一层广场承接主要混战，二层是一条连续开放的回廊，左右楼梯把两个楼层接起来。楼群需要有柱梁、楼板边缘、门窗框、层间色带和简洁檐口，读起来是校园建筑，不是一圈货架、摊位或六个摆在地上的小盒子。

整体占地 80×64 m 包含建筑、入口、边缘和活动空间，不等于全部都是空白战场。中心约 36×30 m 的争夺区保持通透，周围留出接近、绕行、楼梯落脚和追逐空间。空间扩大主要通过地面跨度、走廊长度和建筑模数复用实现，角色、门窗、道具和掩体不跟着同比例放大。不得靠增设深房间让地图显得更大。

两层楼面的初始高差为 4.5 m，二层通行净宽 4.5 m，楼梯净宽 4 m。楼梯按约 30° 的坡度预留约 7.8 m 水平展开，平台另计；两层总建筑轮廓约 9–10 m 高。上述是草模起点，用户确认的是可行走双层、走廊互通和楼梯连接，细部尺寸由碰撞与相机验证调整。

一层主要表达创客社和桌游社，二层表达音乐、摄影、动漫、篮球四个社团。初始布置与图一接近，但允许随构图、楼梯和主路线移动，不牺牲连通性去追求招牌的绝对坐标。其余校园立面可以有规则窗格和实体墙段，但不能增加新的社团招牌。每个社团房间只做短侧壁、后墙、顶面和门窗框，让外部看得见室内深度；房间内部不是通行路线，也不成为 Persona 的隐藏落点。

中央不放树、雕塑或永久高台。六边形预警使用薄平面色标和游戏表现，不作为碰撞凸台。固定掩体放在争夺区周边，形体用低矮方块、梯形或六边形柱；间距围绕抓取、接近与打断吞噬安排，不是随意撒一堆方块。少量小型几何树位于建筑边缘和固定花池中，树冠只用少数块面。前侧坠落缺口、入口和返回区由精确布局决定，不让生成模型额外添加悬崖裂口。

材质使用无纹理的纯色大面或等价颜色表达，轻微色阶帮助辨认朝向。UI 的深色描边转译成门窗框、图标轮廓和少量建筑压边，不要求把每块地砖或三角面都描黑。UI 的柔和边角转译为少量单段倒角，建筑仍保持方块、梯形、六边形结构；不使用鼓包、充气玩具、细密倒角或光滑写实雕塑。

明亮柔和的日光让地面与二层走廊都可读，阴影略深于本体即可，不把室内压成黑洞。禁止写实砖纹、木纹、刮痕、脏污、金属反光、法线细纹和复杂 PBR。不要用景深虚化掩盖模块接缝和结构错误。

The Hand 与静态校园分开。开掌和拳头沿用 UI 暖黄色和方块化轮廓，一层从天空向下掌拍，二层从可见空域接近后挥拳；二层内侧应敞开，不让屋檐挡住手的合理接触路线。手只在后续整体场景展示中组合，校园资产参考图不把手焊进建筑里。

## 3. 提示词如何使用

六组完整文本分别保存在对应 `.txt` 文件中；`prompts.json` 保存模板、引用图角色、尺寸选项和模型参数。`prompt-validation.json` 仅记录字符长度与变量替换校验，不能解释成 API 已接收或参考图已验收。

| 文件 | 输入与用途 | 验收重点 |
|---|---|---|
| 01_campus_entrance.txt | 原校园图＋原平面图＋UI 首页＋确认后的入口视角草模 | 80×64 m 校园体量、两层连通、楼梯、一层两社团二层四社团、UI 风格 |
| 02_campus_overview.txt | 已通过的校园入口图＋同一草模高位视图＋UI 首页 | 只换视角；建筑、楼梯、缺口、房间和社团数量不漂移 |
| 03_campus_bay_single.txt | 已通过校园图＋UI 首页＋单件立面草模 | 只生成一个有浅层室内纵深的立面，接口与比例清楚 |
| 04_hand_open.txt | 原校园图中大手造型参考＋UI 首页＋完整手形草模 | 单独右手、五指关系、暖黄色、清楚分段，便于本地姿态制作 |
| 05_hand_fist_optional.txt | 已确认开掌参考＋UI 首页＋拳形草模 | 同一只手的握拳姿态；仅在无法本地改姿态时启用 |
| 06_style_correction_optional.txt | 结构已经通过的校园图＋UI 首页 | 只修配色与材质，不能借风格修正改变布局 |

当前部分输入标为 `approved_*`，这些是未来需要制作并验收的输入角色，不是已经存在的文件。原图、UI 和草模是不同用途的参考，不能把它们直接作为 3D 多视角组。

先读图、再形成精确布局、再准备参考图，最后才调用接口。整体两张校园图用于设计一致性；真正交给 `image-to-model` 的是单件建筑或单只手的已确认图片。图生 3D 阶段不额外塞入接口不支持的长提示词，也不要求 3D 接口读取玩法规则。

图像阶段候选使用 `seedream_v5`；校园参考图为 3072×1728，独立资产参考图为 2048×2048。几何阶段维持 P1，建筑试样 6000 面上限、手部各 4000 面上限，`texture=false,pbr=false`，之后本地分配 UI 共享材质。最终提交前对真实输入运行 CLI dry-run，核对端点、参数、模型和费用；本次没有假造文件来声称 dry-run 已通过。

## 5. 按阶段验收，不用反复抽卡代替修改

1. 先查结构：两层、连通走廊、两座楼梯、六社团楼层、中央空区、缺口。任一错误先修草模或输入图，不继续转 3D。
2. 再查风格：与真实 UI 并排对照，检查中性色大面、粉彩、深色结构框、简单块面和轻微阴影。不合格才用定向风格修正提示词。
3. 单件资产检查轮廓、厚度、背面、拼接面、门窗纵深和独立性。漂浮装饰和细腿等不合需求的几何必须处理。
4. 本地组装时恢复精确尺寸、UI 材质色值、社团图标与碰撞；生成结果的近似比例不直接变成游戏规则。
5. 场景内检查镜头、Persona 可达性、二层落地韧性清零且只掉 1 个不传送、出界返回、大手动作与击中一致。网格生成成功不能代替上述验收。
