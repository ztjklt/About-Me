# About Me：320 种额外 Persona 素材与 100 种新机制策划

日期：2026-10-04。策划基线：`0fef7d3`。文件名保留 `200` 以延续任务交接；最终规模是 **320 个道具候选、100 个道具/环境新机制、另加 10 个抓拖与挣脱改良**。这份策划与配套 JSON 都是待制作、待实现、待真人验证的规划，不是已经上线的模型库，也不是运行时 catalog。

主任务本轮先补的 `swimming-ring / 游泳圈 / Cushion` 不计入 320。AI 性格皮肤与移除图片识别由主任务交付；这里的皮肤主题、情绪道具和特效不会给皮肤附加战斗数值。只派出本次一个游戏策划，没有再拆代理。本 worktree 只交付这份文档及 `shared/persona-expansion-200.json`。

## 1. 产品方向：先认出“你”，再看见选择和反制

每个道具要满足三件事：能从玩家说出的具体兴趣找到原文证据；不看名字也能认出造型；在“使用、被打落、地面争抢、回收/吞噬”里形成可读行为。新增数量不靠同物换色，机制数量不靠把推力从 5 改到 6。320 件分别有不同的轮廓、兴趣事实和握持方式；允许多个物体复用一个经过验证的规则家族。

原文“我喜欢游泳”默认生成最直接的浮板/泳镜候选中的一件；本轮已上线游泳圈时优先选圈。只有原文明示“浮潜、皮划艇、水球”等不同事实时再选其他物体。不从一句“游泳”刷出二十件生命。AI 只推荐白名单视觉和机制版本，服务器确认具体 assetId、visualId 与版本绑定。

素材量、可生成覆盖量、实际机制量分别记录。每个候选有 `status=planned_no_model_no_runtime_binding`；机制有 `status=proposed_not_implemented`。有造型候选并不证明关键词能成功生成；有机制文本并不证明技能能在游戏里触发。

## 2. 真实实现基线与需要保持的核心

本设计核对了 PRD、最新 STATUS、`GameModel.cs`、`SoftCombat.cs`、`ActiveDollPhysics.cs`、`GameUI.cs` 和三份实际/历史目录。当前 runtime catalog 为 60 项、visual manifest 为 52 项、历史 prop 规划为 81 项（集合彼此重叠，不相加宣称 193 个模型）。新增 320 同时排除三份中的既有 id 与名字，再额外排除本轮游泳圈。

| 项目 | 当前基线代码行为 | 本规划处理 |
|---|---|---|
| 输入 | 单个 `use_item`；G 抓身体、H 抓手持物、E 上下文交互、持续 Q 挣脱；0.05 秒发一次输入 | 保留单攻击按钮；二次使用只用于明确的放置/引爆状态，不能增加隐藏长按重击 |
| 底层模板 | Projectile、Disc、Melee、HeavyWeapon、Utility、Deployable、Summon、SpecialAbility、Ricochet、Tether、Cushion、Barricade 共 12 类 | 新家族通过注册表逐批启用，AI 不发任意逻辑 |
| 物理攻击 | Projectile 把真正装备实例设为 Thrown；其他若干模板创建 Effects；学校圆盘的 ThrownDisc 是特效对象 | 新爆炸视觉结束不销毁真实生命；必须审核效果与真实实例的联结 |
| 生命数 | `Remaining` 统计 ownerId 对应全部非 Consumed 实例，含 Ground/Carried/Thrown | 复制影像、烟花、装置不进入生命计数 |
| 交互 | Ground→Carried；本人 1.5 秒 Recover，别人 2.5 秒 Eat；攻击/抓取可打断 | 新救拖、磁吸、夹取只改 Ground 位置，仍走原交互时长 |
| 吞噬 | 完成才 Consumed，原主数量为 0 才淘汰；吃者不继承能力 | 坚持无偷装备、无回血、无吞噬加 Buff |
| 节奏 | Reveal 5 秒；Battle 第 150/300 秒大手；450 秒直接 `Finish(timeout)` | 不把旧 PRD 15 分钟和最终全爆抢夺写成已实现；本轮不改结算规则 |
| 超时排名 | 非淘汰优先、吞噬数优先、同分再剩余数；允许并列 | 不另塞团队得分来替换当前胜负 |
| 角色 | 真正权威布娃娃和简化回退模拟均存在 | 抓拖/击飞必须分别验证，不能用回退位移证明物理拖得动 |
| 性格能力 | 六主题特效试验台存在，正式对战判定尚未由本规划接入 | 喷火等下列均是需要服务端逻辑的建议，不把代码粒子当命中证据 |

## 4. 机制注册表：100 项新机制＋10 项抓拖改良

JSON `mechanics` 共 110 条。100 项非抓拖条目按不同因果/对象类别/状态转换计数；抓拖 10 项另列，不靠把已有持续 Q 和修改参数凑进“100 新机制”。个别家族复用命中、部署和网络同步基础设施，但“接触爆、可搬定时爆、遥控引爆、感应爆、附着后挣脱剥离”有不同可见状态与反制，不是五个不同冷却的同一爆炸。

每条含独立 id、触发、真实效果、持续/冷却、authority event/state/decision、代价反制、实际试玩脚本和趣味假设。数值为未经真人平衡的起始值；机制表中的 duration/cooldown 是人可读设计值，需要实现时转成固定参数，不由 AI 解析字符串自由执行。

机制默认单选。道具的多个 `mechanicIds` 是互斥候选版本，不能把两三个机制叠成免费能力。联机 public asset 应公开机制版本图标，方便陌生人理解对手；不得公开自我介绍原文。施力系统以服务器权威为准，客户端只表现、预测与发意图。

### 首批实际实现建议（12 项，不一次启用 100 项）

| 顺序 | id | 最小可玩的重点 | 必须成功的真人反制 |
|---|---|---|---|
| 1 | fuse-burst | 可搬运定时烟花，倒计时和爆风一致 | 乙拾回扔还；甲也会被误炸，生命实例不删除 |
| 2 | impact-burst | 接触点与墙遮挡明确 | 墙后不受力；步行避开落点 |
| 3 | ring-burst | 一道扩散薄环 | 跳过环不削韧、不推力、不打断 |
| 4 | spring-pad | 双方可用小弹床 | 对手借弹床占位；拆床后角色安全落地 |
| 5 | water-jet | 方向水柱与后坐 | 绕侧、墙挡，施放者也退步 |
| 6 | wet-trail | 只减制动的可视湿地 | 玩家输入仍原方向，跳干地可摆脱 |
| 7 | tractor-loose | 地面抢夺准备 | 仅Ground受力；敌人取Carried立刻不再拉 |
| 8 | item-push-wave | 推物不推人 | 不能打断已Carried交互，不能改ownerId |
| 9 | front-shield | 方向明确的两击盾 | 背抓有效，不能持盾吞噬 |
| 10 | false-drop | 假物有可辨纸边 | 不计生命、不进Eat记录，近触识破 |
| 11 | hologram-route | 原创全息脚步路径 | 没有攻击/碰撞；不藏真实昵称和掉落轮廓 |
| 12 | own-item-beacon | 原主寻找遗失人格 | 仍要回收计时；对手能抢吃，墙后不揭人物 |

先让一次按键能产生明确事件，再做单个组合：水柱推物→湿地制动→跳弹床→抢回生命。二阶段候选为遥控/附着爆、撑锚、反射、回收屏、转台；三阶段才做双端门/索道/绳桥等状态量大的机制。12 项首批建议不是本策划已经实现的 12 项。

### 手机、键鼠与反馈

被抓时在人物附近及逃脱按钮都显示同一进度环，标签为“按住挣脱”；环色以外有数值/刻度。触控 hit area 至少64逻辑像素，允许按住后手指小幅滑出按钮仍保持捕获，pointerUp/cancel/失焦一律释放。Q 不要求连点，禁止把高频设备当优势。可设置“点一下开始持续挣脱，再点停止”的可访问模式，服务器仍按持续时间判定，不能加速；需要单独标 UI 模式并验证同等效果。

张力在抓绳/双手接触处显示由松到绷的形态和轻微震动，不能只靠红绿。抓者转弯看到目标身体随弧线移动，被抓者逆走看到脚步与绳角变化。受击释放、绕柱断链、Q成功、时间到松手各用不同的简短动作/提示。触控不开全屏测试；至少720高窗口和手机安全区两种证据。

多人二期：每目标最多2条链，合成总力封顶等于单链上限的1.25倍，双向力抵消；Q同一次持续操作解除全部当前链并统一免抓。第三人剪链只剪最近1条。多链不重复计算每秒9削韧、掉落或逃脱计时。抓者互抓环/三角环禁止，断线与倒地起身立即按现有规则收敛。此功能需要明确版本和测试，不作为当前已实现内容。

### 最低真人试验

2人直拖：甲向前走，乙无输入；2秒内可感1–2米拖距，不要求所有姿态固定距离。随后乙逆走/持续Q，确认能稳脱且脱后有走离窗口。90°转弯、绕柱、临边拖、倒地拖、抓手持物、第三人打断分别至少10次；真实布娃娃与回退各记录。临边坠落只走现有掉1件规则，不能拖一下就消灭生命。

网络100–150ms往返、20ms抖动和1%丢包下跑同套，不把本地自动局称为异地真人局。Q短松80ms应容错，180ms开始衰减；失联>350ms/失焦不能自动完成逃脱。触控使用真实手指/设备才证明捕获和可访问性。先记录成功率、错抓率、平均脱离时长、净拖距、主观控制感与爆笑瞬间，再决定最终参数。

## 6. 服务器与客户端交接接口

### 受控资产绑定

运行时仍由服务端校验 `templateId/visualId` 允许组合。新增 `mechanicId + mechanicVersion` 必须在注册表白名单中，AI 不能发力/伤害/碰撞代码。规划 JSON 不得直接替换 catalog。前期模型只绑定 `stage_0_template` 时使用既有行为，按钮说明不能预告还没实现的冰冻、喷火、爆炸。

新增对战机制前协商 protocol 4（当前 protocol 3 固定，客户端会拒不匹配），或先为现有协议增可忽略字段并有明确旧客户端降级。不可单方面发新版字段假设旧客户端会正确做新机制。角色隐私保持：只同步当前公开道具与掉落资产，不同步 source/intro 与私有全背包。

### 建议状态与事件

保留已有 `Command(sequence,x,z,yaw,action,itemId,run,escapeHeld)`；`use_item` 是唯一攻击意图。二次使用由服务器根据当前 `sourceInstanceId` 关联的部署状态决定，无需再加遥控按键。`interact` 只处理原回收/吞噬或明显标记的公共机关；不能让 UI 猜测吞噬结果。新增机关交互宜用 `contextKind` 或独立白名单 action，必须明确玩家提示与版本。

新 `MechanicEffectState` 建议包含：effectId、mechanicId/version、sourceInstanceId、ownerId、startedAt/expiresAt、pose/velocity、shape、phase、targets、charges、hitOnceSet、publicWarning。JSON 各 authority event 是事件语义名称，不是已存在的C#消息类型。服务器写 `mechanic_start / phase / hit / canceled / expired`，并携 effectId、serverTick、targetId 和 reason；每项实际 resolved 名见 JSON。客户端只用事件驱动粒子、音效、动作和警示圈，命中显示应对齐serverTick。

每 tick 使用同一前步位置，先判合法目标/视线/相位，再合成外力，再交给移动/权威物理；禁止各客户端 AddForce 各算结果。冲击同一 effectId 对同一目标只一次，逐段效果有显式段号；同帧总冲量封顶，GetUp保护仍先判。墙遮挡在爆风、绳、吸力、光门中分别验收；动作取消、掉落、Consume、Disconnect、Finish都清关联状态。

### 生命状态不可破坏

- Equipped 出技能可产生效果副本；它不是可吞噬的新生命。source实例被打落时，装备持续技能终止；已独立投出的有限弹体是否保留由机制版本固定，不能因网络重连重复发射。
- 如果采用真正投出source实例：其状态为Thrown，落地为Ground，爆炸只结束攻击组件和粒子，**真实实例仍留Ground**。爆炸不能凭空把主人生命计数减1或自动恢复Inventory。
- Ground可被轻推/浮托/吸附，但Carried交互锁定期间不受“吸物”影响；主人仍1.5秒回收、敌人仍2.5秒吞噬。装置回收不是Persona回收，不能复用Consume毁掉生命。
- Consume按 instanceId 幂等，取消效果后记录一次EatRecord；假物没有instanceId生命周期，更不进入胜负。一次爆风可打落，但不直接Consume。
- 角色坠落执行现有掉落1件，救援绳不免代价。不能把生命推到无法回收区域，统一SafeDrop/边界救回；Final/Finished中不得残留攻击。
- 机制控制限制时长、重复保护和总力；吞噬没有获得新技能、恢复生命、持久能力或隐藏Buff。

### 制作规格与可辨识门槛

配套 JSON 每条 `model_spec` 有独立 silhouette、尺寸档、碰撞预算、Grip/Swallow锚。S最长0.45m、≤900三角；M最长0.85m、≤1500三角；L最长1.2m、≤2400三角。LOD1约50%，LOD2约20%；单材质512图集（可以多个道具共图集），不默认每件独占大贴图；无骨骼道具优先，机械活动部件最多2个。厚度/圆角/大手柄保证玩具风与远距辨认；泳镜的双镜杯、脚蹼的长鳍、浮板握孔必须保留。

每件必须提供独立Prefab或可生成的独立几何配方、visualId、缩略图、模型许可/原创记录、主色、Grip、SwallowCenter、地面尺度、凸碰撞和LOD。不得用一个圆球只改色声称完成320件；一个资源含多个独立有差异部件仍要逐项截图和检视。道具生命碰撞统一在规则允许边界内，视觉大小不会无意让角色攻击范围翻倍。大型物吞噬动画允许缩小显示，服务器资产身份、计时不变。

每批验收：无文字/贴图条件下轮廓识别测试；角色跑/转/跳/倒地不穿模；地面能看见且能交互；吞噬看得到入口动作；6人同场不遮挡按钮/相机；道具主色改变不影响辨识。模型生成器输出后要修尺度、法线、碰撞与材质，生成成功不等于游戏资产通过。

## 8. 预算、分期与真人验证

以下是待设备实测的预算目标，不是本次性能测量。默认一场不启用100个独立系统，按房间机制白名单只开12–20类；同一玩家最多1个持续装备状态、1个公共部署体，房间同时动态mechanic effects≤24、带刚体部署体≤8、单玩家新效果上限≤4/秒。复杂机关仅使用地图预批准挂点，拒绝任意改校园碰撞。

效果每次最多48可见粒子、无实时点光/不投阴影，远处缩为符号。固定tick50Hz，不给每颗彩纸一个网络刚体；网络快照预计10–20Hz，特效只同步确定性参数与事件。真实生命资产数量不因VFX清理而受影响；存活Ground实例的上限来自真实生成数量，不能为省性能定时删生命。包体把新增模型分组预加载/按需缓存，开局先预热双方实际道具，不将320件全常驻。

平衡假设：新机制应扩展走位/地面资产选择，不能让高频标签拥有更多生命和无反制控场。吞噬对局节奏沿现有450秒，机制若让平均回收/吞噬显著停滞就减少场地持续与占用。目标值只作开始试验的门槛：第一次能看懂/成功用技能的人≥80%，Q触控成功≥90%，明确能说出失败反制的人≥70%，至少1次可复述的社交事件/人/局；这些不是已测结果。

## 9. 交付验证与限制

当前交付没有模型文件，没有运行代码变更，没有新增机制的实际真人局/设备性能证据；本轮只完成官方研究、可实现的接口方案、机器可读候选和验证。后续由主任务整合源码，并分别指定客户端、美术和后端实做与验收。策划建议和实现中调整要回写机制版本，不覆盖用户已有资产。
