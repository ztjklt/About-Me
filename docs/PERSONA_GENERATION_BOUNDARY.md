# Persona 生成与公开边界（原型）

## 数量与来源

- 本地样例是固定测试资产，用来覆盖已发布玩法模板；它不代表真实 AI 的返回数量。真实生成按介绍中的辨识度、可视化和游戏化价值选择，可返回不同数量。当前服务端最多接受 **12 件 / 玩家**，六人房最多 72 件。这是原型的对象数与响应长度预算，不是每次必须生成的件数；上线前需按真机和多人性能结果复核。
- 每件真实 Persona 的 `source` 必须是非空、可在玩家介绍中找到的连续原文片段。名称不能替代来源。相同片段及常见表达变化（如“喜欢篮球”“热爱篮球”）合并为一件。模型仍负责语义选择，规则校验负责可核对性和明显重复；复杂同义句尚不能仅凭规则完全识别。
- `source` 留在受鉴权的本人资料和服务端存储中，用于来源核对与整套重新生成判定。联机公开投影只允许 `assetId`、`name`、`templateId`、`visualId`、`color`；介绍原文、`source`、其他内部字段不得进入房间快照、物品事件或调侃请求。联机与后端主责负责投影与协议整合。

## 内容边界

- 提示词要求跳过联系方式、账号、证件、精确住址、医疗诊断、性取向、宗教信仰和攻击性内容，且名称不得复制介绍原句或个人隐私。
- 服务端对 `source` 和公开名称进行确定性拦截：邮箱、网址、长号码、常见联系与证件关键词、具体门牌住址、明确辱骂及色情/仇恨词。被拦截的候选不保存；若无安全候选则本次生成失败，旧资料保持不变。
- 这是原型级规则，不能替代正式内容审核：隐晦的个人信息、方言谐音、语义歧视和复杂同义事实可能漏检。玩家可见内容在发布前还需测试与审核负责人复核；调侃输出另由联机与后端主责审核。

## 验收证据范围

`server/tests/test_api.py` 使用本地构造的模型输出，覆盖 1 件、9 件、12 件上限、空或不在介绍中的来源、重复篮球事实、电话与精确住址、明显攻击性名称。它不证明真实模型质量、生产级内容审核或六人真机性能。
